# Сравнение архитектурных подходов для системы мониторинга ферм

## 1. Автономная Edge-архитектура

### Контекст
- Все ключевые сервисы развернуты на Edge Node (ферме)
- Сервисы: видеоаналитика, детекция беспокойства и драк, трекинг животных, управление кормушками/поилками, мониторинг здоровья, учет поголовья, локальная аналитика, локальная аутентификация
- Синхронизация с облаком минимальная: только предобработанные данные и метрики, если интернет доступен

### Преимущества
- Полная автономность: работает без интернета, низкая задержка на обработку инцидентов (<5 секунд)
- Горизонтальное масштабирование через добавление вычислительных ресурсов на ферме (больше GPU/CPU для видеоаналитики)
- Минимальные задержки при аварийных событиях, все решения принимаются локально

### Риски и ограничения
- Обновление сервисов сложнее, чем в облаке
- Ограничена производительность на Edge (количество потоков видео, мощность AI)
- Требуется достаточная аппаратная инфраструктура на каждой ферме

### Вывод
Автономная архитектура оправдана для максимальной отказоустойчивости и минимального времени отклика. Подходит для ферм, где связь с интернетом нестабильна.

## 2. Гибридная Edge + Cloud архитектура

### Контекст
- Edge Node выполняет только первичную обработку: захват видео, детекция критических инцидентов, управление датчиками и оборудованием
- Облачная платформа: хранение исторических данных, глобальная аналитика, прогнозы запасов, учет поголовья, авторизация пользователей, сложные вычисления AI
- Edge синхронизирует только предобработанные данные и критические события

### Преимущества
- Edge легковесный, меньше ресурсов на месте
- Простое обновление и поддержка сервисов через облако
- Централизованная аналитика и прогнозирование, возможность глобального мониторинга нескольких ферм
- Снижение нагрузки на сеть (только предобработанные данные отправляются в облако)

### Риски и ограничения
- Зависимость от интернета для облачных функций
- При недоступности облака аналитика и прогнозы будут ограничены
- Первичная обработка инцидентов все еще должна быть достаточно быстрой, чтобы локально генерировать алерты

### Вывод
Гибридная архитектура подходит для масштабируемого SaaS-подхода и централизованного мониторинга. Позволяет снизить стоимость Edge узлов и упростить поддержку, но снижает автономность фермы.
