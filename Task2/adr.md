## Bounded Contexts

### 1. Animal Monitoring Context (Видеоаналитика и инциденты)

**Ответственность:**
Обнаружение поведения животных, распознавание событий и фиксация инцидентов.

**Функции из ТЗ:**
- Фиксировать признаки беспокойного поведения или драк
- Фиксировать признаки задавливания поросят
- Оценивать состояние животных по внешнему виду и поведению (болезнь, гибель, беспокойство)
- Обеспечивать реакцию <5 секунд

### 2. Animal Tracking Context (Трекинг и траектории)

**Ответственность:**
Удержание идентичности животного во времени, построение траекторий и оценка стабильности трека.

**Функции из ТЗ:**
- Отслеживание животных (глобально и локально)
- Подтверждение устойчивости событий (проверка, что «драка» не ложная)
- Консолидация треков с разных камер и корпусов
- Пересчёт поголовья

### 3. Device Control Context (IoT-управление оборудованием)

**Ответственность:**
Управление кормушками, поилками и системами фермы.

**Функции из ТЗ:**
- Управление кормушками и поилками разных производителей
- Следить за состоянием систем фильтрации воды
- Собирать телеметрию и статусы

### 4. Inventory & Feed Management Context (Учёт кормов и прогнозирование)

**Ответственность:**
Учёт и прогноз расхода еды.

**Функции из ТЗ:**
- Следить за запасами еды
- Прогнозировать расход

### 5. Synchronization & Event Integration Context (Edge ↔ Cloud синхронизация)

**Ответственность:**
Надёжная передача событий между Edge и Cloud, синхронизация при потере связи.

**Функции из ТЗ:**
- Передача событий в центральную систему (с задержкой ≤10 мин)
- Повторная отправка при восстановлении связи
- Консолидация событий и метрик

### 6. Behavior Analytics Context (Глобальная аналитика и метрики)

**Ответственность:**
Хранение и анализ данных, построение отчётов, поведенческая аналитика.

**Функции из ТЗ:**
- Аналитика событий
- Расчёт метрик
- Предоставление данных в другие системы

# Интеграции

## Edge ↔ Cloud коммуникация

### Шина / Очередь: MQTT + HTTPS (REST/gRPC)

**MQTT** — лёгкий publish/subscribe протокол, оптимален для нестабильных каналов связи и IoT-данных.
- Позволяет буферизовать данные на Edge и гарантировать доставку при восстановлении связи.

**REST/gRPC** — используется для передачи агрегированных данных (batch) и запросов от облака (например, управление конфигурацией Edge-агентов).
- Возможна реализация на AWS IoT Core, Azure IoT Hub или EMQX в частном облаке.

## Локальная коммуникация (Edge)

### Шина событий: Local Event Bus на базе Redis Streams или NATS

Локальная шина событий обеспечивает реактивную интеграцию между модулями с минимальной задержкой (<100 мс).

**Redis Streams / NATS** — лёгкие, отказоустойчивые и могут работать офлайн без интернета.
- Позволяет обрабатывать параллельные видеопотоки и телеметрию, масштабируя через докер-контейнеры.

## Облачная коммуникация

### Шина / Очередь: Apache Kafka или RabbitMQ
- **Kafka** — стандарт для потоковой аналитики и интеграции с BI / ML-модулями.
- **RabbitMQ** — альтернатива, если приоритет в простоте и совместимости.
- Поддерживают масштабируемую агрегацию данных с десятков edge-узлов.
- Позволяют строить пайплайны данных (ETL, stream processing, anomaly detection).

## Протоколы управления устройствами (Edge)

### IoT-уровень: MQTT, Modbus/TCP, OPC-UA

**Обоснование:**
Унифицированные промышленные протоколы обеспечивают совместимость с оборудованием разных производителей.

- **MQTT** — для умных сенсоров (температура, движение, влажность).
- **Modbus/OPC-UA** — для тяжёлых контроллеров и систем жизнеобеспечения (вентиляция, фильтрация, насосы).
